### Android 构建链（WSL 本地）

按 [apps/android/README.md](../apps/android/README.md) 的刷新与构建步骤：

1. `nsh package --target android --abi arm64-v8a` ✓（libnsh.so 交叉编译 28.1s；
   debug key 签名警告为 spike 预期，release 签名属后续事项）。
2. 解包 `.nsh/out/Pandex.apk`，刷新 `jniLibs/arm64-v8a/libnsh.so` 与 `assets/nsh/` ✓。
3. `gradle :app:assembleDebug :app:assembleRelease :autofill:lintDebug` ✓
   （BUILD SUCCESSFUL 14s；`Unable to strip libnsh.so` 为 M0 已知现象，release so 已 stripping）。
4. `python3 test_m0_autofill_apk.py -v` ✓（2 tests：debug 单 APK 含 autofill 服务与 NSH 产物，
   release 排除 spike 组件）。

**产物 sanity check**：新 `libnsh.so` 含 core 特有的 `EmptyPassword` 错误类型字符串、
不含旧演示密码 `correct-password`；`correct horse` 完整串被 LLVM 常量折叠为立即数比较
（`correct`/`horse` 片段在二进制中），据此判定产物确为第 3 阶段代码而非过期产物。

**范围说明**：本阶段为构建链回归，未做真机验收（回归时无 adb 设备连接）；
M0 门槛 1–3 的真机结论不受影响，如需真机冒烟另行安排。

### Windows 构建链（GitHub Actions）

WSL 本地不构建 Windows（见 [dev-environment-wsl.md](dev-environment-wsl.md)），
回归以 CI `windows-package` job 为准。`ccd07cc` 推送触发 run
[45649226798](https://github.com/pandas-coding/pandex/actions/runs/45649226798)：

- `check`（ubuntu-latest，fmt/clippy/test）✓ 1m26s。
- `windows-package` ✓ 34m29s：
  - `nsh package --target windows --out .nsh/out` 产出 `Pandex/`（含 exe）、`Pandex.zip` bundle
    与 `Pandex-setup.exe` 安装器；
  - 冒烟测试通过：exe 启动后存活 5s 无退出（脚本未 throw），随后强制结束；
  - artifact `pandex-windows` 上传成功（34,955,416 bytes，ID 15040168183）。
  - 耗时归因：`ccd07cc` 变更了 `Cargo.lock`（新增 pandex-core），CI 缓存 key 随之变化，
    restore-keys 命中旧缓存后 Rust crate 重编译 19m7s + Windows runner 7m54s；
    新缓存已写回，后续运行应回到 ~15m 量级。
  - 唯一 annotation 为 actions Node.js 20 弃用警告（cache/checkout/upload-artifact 被强制
    跑在 Node 24），不影响结果；升级 actions 版本属后续维护事项。
